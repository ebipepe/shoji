# 開発履歴（Development History）

Shoji（旧名 `koukoku_blocker`）の各ファイルの目的・設計思想と、改修の経緯をまとめた記録です。
「なぜこうなっているのか」を後から追えるように、問題 → 原因 → 対処の順で書いています。

- 日時は日本時間（JST）です。
- 初版の日時は、開発用の Windows PC へ配置した時刻です。

---

## 1. 設計思想

1. **すべて PC の中で完結させる。** 外部サーバーを持たず、テレメトリーも送らない。広告ブロッカーが新たな追跡元になっては本末転倒なので。
2. **ブラウザ拡張ではなく、PC 全体のフィルタにする。** HTTPS フィルタリングプロキシと DNS フィルタの二段構えにして、ブラウザの種類を問わず、アプリ内広告にも効かせる（AdGuard for Windows と同じ方式）。
3. **ルールは実績あるコミュニティのフィルタリストを使う。** EasyList・AdGuard・uBlock Origin のリストをそのまま読めるエンジンを自作し、独自ルールは最小限にする。
4. **壊すより通す。** フィルタリングで困るのは「サイトが表示できない」こと。迷ったら処理せずに通す側に倒す（証明書を拒否するアプリの自動除外、CSP の慎重な扱い、YouTube のデータ改変は広告部分に限る、など）。
5. **元に戻せること。** システムのプロキシや DNS を変える処理は、必ず元に戻す手段（終了時の自動復元・復旧用バッチ）を用意する。

### 改修 1 — 証明書が信頼されていない状態で全 HTTPS サイトが開けない（2026-10-17 23:06 頃）
- **症状:** YouTube の動画が再生できない。ぜかましねっとが「接続がプライベートではありません」（`ERR_CERT_AUTHORITY_INVALID`）になる。
- **原因:** ルート証明書を Windows に登録する前から HTTPS を復号していたため、すべてのサイトが証明書エラーになっていた。さらに、拒否されたサイトを 1 件ずつ除外する仕組みだったので、動画配信サーバーのように新しいホストが次々に出てくる場合は毎回エラーになっていた。
- **対処:** 起動時に証明書の登録状況を確認し、未登録ならその場でインストールを促すようにした。登録を確認できるまでは HTTPS を復号しない。短時間に多数のサイトで拒否されたら、証明書自体が信頼されていないと判断して復号を止める安全装置も付けた。
- **対象:** `main.py` `shoji/context.py` `shoji/proxy_addon.py` `shoji/winsys.py` `shoji/dashboard.py` `shoji/assets/dashboard.html`

### 改修 2 — YouTube が「枠だけ」表示になる（2026-10-17 23:29）
- **症状:** YouTube のトップが灰色の枠だけで、動画一覧が出ない。
- **原因と対処:**
  1. YouTube 内部のデータで、広告と関係ない場所にある `adSlots` などのキーまで削除していた。→ プレイヤー応答（`videoDetails` 等を持つデータ）の中だけを対象にし、フィードでは「広告だけでできた要素」を丸ごと除くだけにした。
  2. 動画データの URL（署名付き）から追跡パラメーター（`ei` 等）を除去していた。→ 内蔵の除去リストはページ遷移のときだけ使い、それ以外の通信にはフィルタリストの `$removeparam` だけを適用するようにした。
  3. YouTube は 1 つのヘッダーにカンマ区切りで複数の CSP ポリシーを送ってくるが、1 つのポリシーとして解釈していた。→ ポリシーごとに処理し、既にインラインを許可しているポリシーには手を付けないようにした。
  4. `$removeparam` だけのルールまで「広告/トラッカーのドメイン」として扱い、Google 系の Cookie を誤って遮断していた。→ 遮断用のルールだけで分類するようにした。
  5. 安全装置が、証明書を正しく登録済みの状態でも誤作動していた。→ 登録を確認できた場合は全体停止しない。
- **対象:** `shoji/youtube.py` `shoji/assets/content.js` `shoji/privacy.py` `shoji/proxy_addon.py` `shoji/injector.py` `shoji/filters.py` `shoji/context.py` `main.py` `shoji/dashboard.py` `tests/test_core.py`

### 改修 3 — 「途中で切れた接続」を「証明書の拒否」と誤判定（2026-10-17 23:35 頃）
- **症状:** 対象外の一覧に YouTube・Google が次々に入り、Edge でも処理されない。
- **原因:** ブラウザは高速化のために接続を先に張っておき、使わなければ切る。それを証明書の拒否と数えていた。
- **対処:** mitmproxy のエラーのうち、本当に証明書を拒否したもの（`unknown ca` 等）だけを数えるようにした。一度でも正常に処理できたサイトは除外しない。
- **対象:** `shoji/proxy_addon.py` `shoji/context.py`

### 改修 4 — Firefox の拒否が Edge にまで波及（2026-10-17 23:39）
- **症状:** Firefox（独自の証明書ストアを使う）が拒否したサイトが、Edge でも処理されなくなる。
- **対処:** 接続元のアプリを Windows の TCP テーブル（`GetExtendedTcpTable`）から特定するようにした。Firefox の各プロファイルには、Windows の証明書を使う設定（`security.enterprise_roots.enabled`）を `user.js` に自動で追記する。
- **対象:** `shoji/winsys.py` `main.py` `shoji/proxy_addon.py` `shoji/context.py`

### 改修 5 — 対象外の単位を「サイト」から「アプリ」へ（2026-10-17 23:48）
- **症状:** 動作確認に使った Claude アプリ内蔵のブラウザが証明書を拒否し、その結果 YouTube が Edge でも対象外になっていた。
- **対処:** 証明書を拒否したアプリ（`claude.exe` `chatgpt.exe` `slack.exe` 等）の通信だけを素通しにした。他のアプリでのフィルタリングには影響しない。接続元のアプリが特定できない場合だけ、従来どおりサイト単位で除外する。
- **補足:** この回の配置では、PC へのファイル転送ツールが古い内容を書き込む問題が起きた。転送後にチェックサムで内容を確認する手順を追加した。
- **対象:** `shoji/proxy_addon.py` `shoji/context.py` `shoji/dashboard.py` `shoji/assets/dashboard.html`
- **確認:** Edge で 17 分間 YouTube を再生し、広告が出ないことを確認した。統計にも広告スケジュールの除去と広告通信の遮断が記録されていた。

### 改修 6 — 統計の水増しを修正（2026-10-18 00:15）
- **症状:** 「動画広告」の件数が 575 件と実態より多く、節約した通信量の推定も過大だった。
- **原因:** 同じ動画のプレイヤー設定を何度も数えていた。YouTube の視聴ログ送信の遮断（トラッカー）も「動画広告」に入れていた。
- **対処:** 動画 1 本につき 1 回だけ数え、実際の広告を止めたときだけ記録するようにした。ページから報告される件数は、通信量の推定に含めない。
- **対象:** `shoji/proxy_addon.py` `shoji/assets/content.js`

### 改修 7 — サイトが自前で貼るアフィリエイトバナーを非表示に（2026-10-18 00:19）
- **症状:** ぜかましねっとのサイドバーに Amazon のバナーが残る。
- **原因:** 画像はサイト自身のサーバーにあり、Amazon へのリンクで囲んでいるだけのアフィリエイトバナーだった。広告配信会社を経由しないので、フィルタリストでは止まらない。
- **対処:** `rel="sponsored"` や主要アフィリエイトのリンクで囲まれた、一定サイズ以上の画像だけを隠す機能（`hide_affiliate_banners`）を追加した。文字リンクと記事中の商品紹介ボックスは残す。
- **対象:** `shoji/config.py` `shoji/assets/content.js` `shoji/assets/dashboard.html`
- **確認:** Edge で再読み込みし、バナーが消えることを確認した。

### v0.2.0 — 普段使いできる常駐アプリへ（2026-10-18 10:00〜13:30）
- 目的: 「Python を入れなくても使える」「異常終了してもネットが切れない」「PC の起動と同時に動く」。
- **タスクトレイ常駐**（`shoji/tray.py`、pystray）。一時停止中はアイコンが灰色になる。
- **Windows の起動時に開始**（HKCU の Run キー。管理者権限は不要）。
- **PAC 方式のプロキシ設定**: 固定のプロキシ指定ではなく自動構成スクリプトを使う。Shoji が止まるとスクリプトが取得できず、ブラウザは自動で直接接続に戻る。
  - 注意点: PAC の `shExpMatch` は文字クラス（`[0-9]`）を使えないため、プライベート IP の判定は JS の正規表現で書いた。
- **見張りプロセス（watchdog）**: 本体の終了を待ち、設定が Shoji を向いたままなら元に戻す。
- **多重起動の防止**（名前付きミューテックス）。2 回目の起動はダッシュボードを開くだけ。
- **一時停止**: プロキシ・DNS とも素通しにする（トレイとダッシュボードから）。
- **ログファイル** `shoji.log`。コンソールなしで動くため必要になった。
- **exe 配布**（PyInstaller、フォルダ形式）。GitHub でリリースを公開すると、Actions が自動でビルド・起動テスト・ZIP 化・添付まで行う（`.github/workflows/release.yml`）。
  - データの保存先は、exe 版では `%LOCALAPPDATA%\Shoji`（exe の置き場所に書き込めないことがあるため）。
- **ライセンス対応**: exe には LICENSE・NOTICE・同梱ライブラリのライセンス全文（`THIRD_PARTY_LICENSES.txt`）を同梱。LGPL のライブラリ（pystray、ldap3）は差し替え可能な .py のまま同梱し、LGPL の urwid・WinDivert は除外。方針は `docs/LICENSING.md` にまとめた。

### v0.3 開発中 — スクリプトレット対応と海外の銀行（2026-10-18 午後）
- **海外の銀行・決済サイトを復号の対象外に**: 英語圏で紹介する前提で、米英欧豪の主な銀行・証券・決済・パスワード管理サービスを内蔵の除外リストに追加した。
  - 内蔵リストは常に適用し、ダッシュボードの一覧は利用者の追加分だけにした（設定ファイルに古い既定値が残っていても新しい内蔵分が効くように）。
- **スクリプトレット（`##+js(...)`）に対応**: 標準のリストにある約 3,500 件のうち約 2,900 件（96%）が動くようになった。
  - uBlock Origin・AdGuard のスクリプトレットは GPL のため、コードは一切使わず、各スクリプトレットの名前・引数・動作の説明だけをもとに `shoji/assets/scriptlets.js` を独自に書いた。
  - ページのスクリプトより先に動かす必要があるため、既存の埋め込みスクリプトの先頭に入れ、CSP のハッシュもまとめて計算する。
  - 実際の Chromium で動作を確かめるテスト（`tests/test_scriptlets_browser.py`）と、プロキシ経由・CSP 付きページでの通し試験を行った。
  - 未対応: `trusted-*`（信頼できるリスト専用で危険度が高い）、`popads-dummy` など利用の少ないもの。
- **フィルタリングログ**（AdGuard の同名機能を参考に、独自に実装）: 直近 3,000 件の通信を、ブロック・通過・変更・復号なし・ページ処理の別、一致したルール、どのページから来たか、応答の状態とともに一覧表示する。「許可」「ブロック」ボタンで、提案されたルールを編集してからユーザールールに追加できる。
  - 閲覧履歴に当たるため、記録はメモリ上だけに置き、ディスクには保存しない。
  - ダッシュボード自身の通信は記録も加工もしない（ログを見るたびにログが増えるのを防ぐ）。
- **迷惑要素リスト**（AdGuard の Annoyances を参考に）: Cookie 同意・ポップアップ・アプリ誘導・ウィジェット・SNS・その他の 6 リストを、ダッシュボードで個別に有効化できるようにした。
  - 表示崩れの可能性があるため初期状態はオフ。オンにした時点でダウンロードして読み込む。
  - 分類「迷惑要素」はページ内（プロキシ）でだけ扱い、DNS では止めない（アプリ全体に影響させないため）。
  - 以前の設定ファイルには新しいリストが載っていないため、起動時に不足分を自動で追加するようにした（既存のオン/オフは保つ）。
  - フィルタリストの表でオン/オフのスイッチが潰れて表示されていた不具合も直した。
- **ダッシュボードのアクセスログを抑制**: 5 秒ごとの状態取得が `shoji.log` を埋めていたため、成功したアクセスは記録しないようにした。
- **exe ビルドの修正**: mitmproxy が Windows で起動時に読み込む WinDivert 関連のモジュール（LGPL のため同梱していない）を、小さな代替品で置き換えた。

### v0.4 開発中 — 要素の選択ブロック（2026-10-19）
- v0.3.0 を公開（スクリプトレット・フィルタリングログ・迷惑要素リスト・海外の銀行の除外）。
- **要素の選択ブロック**（AdGuard の「要素をブロック」を参考に、独自に実装。`shoji/assets/picker.js`）
  - ページ上で Ctrl+Shift+Alt+H を押すと起動。マウスを乗せた要素を枠で示し、クリックで選択。「広げる」「狭める」で範囲を調整し、セレクタは直接編集もできる。「このサイトで隠す」でユーザールールに保存し、その場で隠す。
  - 画面の部品は閉じた Shadow DOM に入れ、スタイルは CSSOM（adoptedStyleSheets）で当てる。`<style>` 要素や innerHTML を使うと、CSP や Trusted Types（YouTube など）で拒否されるため。
  - セレクタは「そのページで 1 つに絞れて、クラスか ID を含む」最短のものを作る。数字の多いクラス名や自動生成らしい名前は避ける。
  - 保存の窓口（`https://shoji.blocker/user-rule`）はどのページからでも呼べるため、**送信元サイト自身の要素を隠すルールだけ**を受け付ける。例外ルール・ネットワークルール・スクリプトレット・CSS の注入・他サイト宛ては拒否し、1 分 30 件までに制限した。
- **ページを毎回取り直す**: ブラウザがキャッシュを再検証（304）すると、前回埋め込んだ古いルールのページが使われ、新しいルールが再読み込みで効かなかった。HTTPS フィルタリング中は HTML の条件付きリクエストのヘッダーを外すようにした。
- **危険サイト対策**（Malwarebytes Browser Guard の方向性を参考に、独自に実装）
  - 新しい分類「危険サイト（security）」。malware-filter の URLhaus・フィッシングのリストと NoCoin のリストを標準で有効にした。ブラウザでも DNS でも止め、広告・トラッカーより優先する。
  - 危険サイトを開こうとしたときは専用の警告画面を出す。広告の警告と違い、自動では閉じない（メールのリンクから開いたタブが黙って閉じると混乱するため）。「危険を理解したうえで開く」で 1 時間だけ許可できる。
- **サポート詐欺（ブラウザロッカー）対策**（`shoji/assets/guard.js`）
  - 「ウイルス」「Microsoft」「お電話ください」などの文言と電話番号、および画面を固める動き（警告の連発、全画面、キーボード・ポインターの固定、履歴の大量追加による「戻る」の無効化、離脱の阻止）を点数化し、**文言と動きの両方がそろったときだけ**反応する。ふつうのニュース記事や、数回だけ確認を出すフォームでは反応しないことを、ブラウザでの試験で確かめた。
  - 検出したら、全画面の解除・キーボードの解放・音声の停止・ダイアログの停止を行い、「このページを閉じる」警告を重ねて表示する。
  - どのページでも、30 秒に 6 回目以降の警告ダイアログは出さない。
- **ブロック率の表示を見直し**: 「ブロック率 30%」が「広告の 30% しか止められていない」と誤解されかねないとの指摘を受け、「通信に占める広告・トラッカー」に改め、件数と説明を添えた。
- **多言語化（日本語 / 英語）**: 英語圏で紹介する前に、利用者が目にする文言をすべて英語にも対応させた。
  - ダッシュボード: `shoji/assets/i18n.js`（約 230 項目）。HTML は `data-i` 属性、スクリプトは `t()` で文言を引く。
  - Python 側（トレイ、ブロック・警告画面、フィルタリングログの説明、操作結果のメッセージ）: `shoji/i18n.py`。
  - ページ内の部品（要素の選択ブロック、詐欺ページ対策）: 埋め込むときに言語を渡す。
  - 言語は設定 `app.language`（自動 / 日本語 / English）。「自動」は Windows の表示言語（GetUserDefaultUILanguage）に従う。
  - 英語は直訳を避け、誤解を招かない表現にした（例: ブロック率 → "Share of traffic that was ads & trackers"）。
  - ログファイル（shoji.log）は日本語のまま（今後の課題）。

### v0.5 開発中 — 「このサイトでは止める」とログの英語化（2026-10-20）
- v0.4.0 を公開（要素の選択ブロック・危険サイト対策・詐欺ページ対策・日英対応）。
- NoCoin のリストの取得が利用者の環境で失敗していたため、リストに予備の配布元（mirrors）を持たせ、失敗したら jsDelivr から取り直すようにした。
- **このサイトでは Shoji を止める**: ページ上で Ctrl+Shift+Alt+P を押すと Shoji の確認画面（`https://shoji.blocker/allow-site`）が開き、「1 時間だけ」か「常に（許可リストに追加）」を選ぶ。ダッシュボードの「許可リスト」には、最近開いたサイトをワンクリックで許可できる一覧も付けた。
  - 最初は要素の選択ブロック（Ctrl+Shift+Alt+H、広告を**追加で消す**ための機能）のパネルにリンクを置いたが、「消す」機能の中に「止める」操作があるのは分かりにくいとの指摘を受け、別のキーに分けた。
- **ショートカットの見直し**: Alt+Shift+P が Chrome 系ブラウザのタブのグループ化と重なっていると指摘を受け、各ブラウザの公式の一覧を調べた。
  - Chrome: Alt+Shift+T（ツールバー）/ I（フィードバック）/ A（ダイアログ）/ N（分割表示）など。Edge も Chrome と同系統。
  - Firefox: Alt+Shift+文字は**ページのアクセスキー**に使われる（Wikipedia では Alt+Shift+H が履歴など）。
  - Windows: Alt+Shift だけで入力言語の切り替え。Ctrl+Alt は AltGr（欧州の配列で文字入力に使う）と同じ。
  - そこで、どのブラウザにも標準の割り当てがない **Ctrl+Shift+Alt+H / Ctrl+Shift+Alt+P** に変更した。文字の入力中は反応しないようにして、AltGr を使う配列での文字入力とも重ならないようにした。
  - さらに、ダッシュボードの「セットアップ」→「ショートカット」で変更・無効化できるようにした（設定 `app.shortcuts`）。ボタンを押してからキーを押すだけで登録でき、修飾キーが 3 つ未満の組み合わせには注意を表示する。英字・数字は Ctrl か Alt を含むことが条件（文字入力と重ならないように）。
  - どのページからでも `shoji.blocker` を呼べてしまうので、**確認画面に埋め込んだ使い捨てトークン**と送信元（Origin）を確かめる。確認画面には CORS ヘッダーを付けず、他のページがトークンを読めないようにした。
  - 同じ問題が既存の「このまま開く（1時間許可）」にもあった（他のページが広告や危険サイトを勝手に一時許可できた）ため、同じくトークン方式にした。
  - 許可リストのサイトに埋め込まれた他サイトの通信でも、危険サイトだけはブロックを続ける。
  - 加工したページを `no-store` で返すようにした。ブラウザに保存された「加工済みのページ」が使われて、サイトを止めても表示が変わらなかったため。
- **ログの英語化**: shoji.log とコンソールのメッセージも表示言語に合わせるようにした。
- v0.4.1 を公開（上の変更をまとめたもの）。

### v0.5 開発中 — 拡張 CSS とスクリプトの代替品（2026-10-20）
- **拡張 CSS（手続き型の要素非表示）**: 標準のリストに約 2,000 件ありながら読み飛ばしていた `:has-text()`・`:upward()`・`:xpath()`・`:remove()`・`:style()` などのルールに対応した。
  - Python 側（`shoji/procedural.py`）がルールを「手順」（JSON）に変換し、ページ内のスクリプト（`assets/procedural.js`）が実行する。ページの変化に合わせて、間引きながら再実行する。
  - AdGuard の `#?#`・`#$#`（CSS の差し込み）・`[-ext-…]`、Adblock Plus の `:-abp-has()` なども同じ手順に変換する。操作の無い `:style()` / `#$#` は、スクリプトを使わず CSS として差し込む。
  - ブラウザの CSS で書けるもの（`:has()` や `:not()` の中身がふつうの CSS）はブラウザに任せる。ただし `:has()` の中の `:has()` は CSS では無効なので手順にする。
  - 全サイト向けの手続き型ルールは、ページを重くするので使わない（uBlock Origin と同じ扱い）。
  - 標準のリストの全 2,554 手順を Chromium で読み込み、正規表現・セレクタとして有効なことを確かめた。
- **$redirect（スクリプトの代替品）**: 広告・計測のスクリプトをブロックしたとき、何もしない代替品を返す。ページ側の `ga()` や `googletag.cmd.push()` が動かずにボタンや動画が止まる、という不具合を防ぐ。
  - Google アナリティクス・タグマネージャー・AdSense・GPT・IMA SDK・FingerprintJS・FuckAdBlock・Amazon apstag などの代替品を Shoji 独自に書いた（uBlock Origin・AdGuard の代替品は GPL なので使わない）。無音の MP3・MP4 は FFmpeg で作成。
  - リストに `$redirect` が無くても、よく使われる Google の広告・計測スクリプトは自動で代替品を返す。ブロックした画像には透明な画像を返す（壊れた画像のアイコンを出さない）。
  - 不具合の修正: `@@…$redirect`（代替品を使わない、という意味）を通信の許可として扱っていた。`$redirect-rule`（他のルールでブロックされたときだけ代替品を使う）を単独のブロックとして扱っていた。
- v0.5.0 を公開。

### v0.5.1 開発中 — フィルターリストの守りの強化（2026-10-22）
- きっかけ: 2026 年 10 月の PHP の重大な脆弱性の報道。Shoji 自体は PHP を使わないが、標準のリストの配布元の一つ（Peter Lowe's list）は PHP で動いている。配布元が乗っ取られて細工したリストが配られた場合に備えた。
- **ドメインの一覧だけのリスト**（Peter Lowe's list、AdGuard DNS filter。設定 `format: "domains"`）からは、ドメイン単位のルールだけを使う。要素の非表示・スクリプトレット・URL のパターン、`$document`（サイト全体の除外）や `$badfilter`（他のリストのルールの無効化）は読み込まない。
- **危険サイトのブロックは、広告・トラッカーのリストの例外ルールでは解除されない**ようにした。解除できるのは、利用者のルール・許可リスト・危険サイトのリスト自身だけ。これまでは、どのリストの `@@` でも、DNS と通信の両方で解除できてしまっていた。`$document` の例外で除外されたページでも、危険サイトは止める。
- **ダウンロードしたリストの確認**: ウェブページ（エラー画面）が返ってきた、ルールが 0 件、64 MB を超える、ルールの数が前回の半分未満に急に減った、のどれかなら使わず、前回の内容を使い続ける。理由はダッシュボードの「フィルタ」タブに表示する。「今すぐ更新」は、減少の確認をせずに取り込む（リストが正当に小さくなった場合のため）。

- **PC を元に戻す**: 「セットアップ」→「Shoji を PC から取り除く」。自動起動・プロキシ・DNS・Firefox の設定・証明書をまとめて戻す。SignPath Foundation（無料のコード署名）の条件「アンインストールの手段」にも対応。

- **文書**: プライバシーポリシー（`docs/PRIVACY.md`）、コード署名の方針（`docs/CODE_SIGNING.md`）、README のアンインストールの節。

## 4. 教訓

- **HTTPS を処理する前に、証明書が信頼されているかを必ず確かめる。** 確かめないまま処理すると、全サイトが壊れる。
- **「接続が切れた」と「拒否された」を区別する。** ブラウザは先読みの接続を頻繁に捨てる。
- **巻き添えの範囲を最小にする。** 1 つのアプリの問題で、他のアプリの処理まで止めない（サイト単位ではなくアプリ単位で除外する）。
- **巨大なサービスのデータは、必要な部分だけ慎重に加工する。** 似た名前のキーが関係ない場所にもある。
- **CSP は 1 ヘッダーに複数のポリシーが入りうる。**
- **署名付き URL のパラメーターを消すと壊れる。** 追跡パラメーターの除去は、ページを開くときだけにする。
- **常駐ソフトは「落ちたとき」を先に設計する。** 固定のプロキシ指定は、本体が落ちるとネット全体を止める。PAC なら自然に直接接続へ戻る。
- **配置後は内容（チェックサム）で確認する。** 「書き込み成功」の表示だけを信じない。
